## Cleanup Steps for `frontend` Branch

To properly clean up the `frontend` branch before merging:

### Step 1: Remove Python Cache Files

```bash
# On the frontend branch
git filter-branch --force --index-filter \
  'git rm -r --cached --ignore-unmatch __pycache__' \
  --prune-empty --tag-name-filter cat -- --all

# Or using git-filter-repo (recommended, faster):
git filter-repo --path __pycache__ --invert-paths
```

### Step 2: (Optional) Migrate Large Files to LFS

If you have Git LFS installed and want to use it:

```bash
# Install Git LFS if not already installed
git lfs install

# Migrate existing files to LFS
git lfs migrate import --include="*.tar.gz,*.csv,*.parquet,*.pt" --everything
```

### Step 3: Verify Cleanup

```bash
# Check that no cache files remain
git ls-files | grep __pycache__

# Check LFS status (if using LFS)
git lfs ls-files
```

### Step 4: Force Push (⚠️ Warning: This rewrites history)

```bash
# Only do this if you're sure!
git push origin frontend --force
```

## Best Practices Going Forward

1. **Always commit .gitignore first** - The .gitignore is now in place on `main`
2. **Review git status before committing** - Check that no unwanted files are being added
3. **Use Git LFS for large files** - Configure LFS before committing large data files
4. **Regular cleanup** - Periodically review repository for unwanted files
5. **Pre-commit hooks** - Consider adding pre-commit hooks to prevent common mistakes

## Alternative: Starting Fresh

If the git history on `frontend` is not critical, consider:

1. Create a fresh branch from `main` (which now has .gitignore and .gitattributes)
2. Copy over the source code files manually (excluding __pycache__)
3. For large files, either:
   - Use Git LFS from the start, or
   - Store them externally and document how to obtain them

This approach gives you a clean git history without the need for force pushes.
